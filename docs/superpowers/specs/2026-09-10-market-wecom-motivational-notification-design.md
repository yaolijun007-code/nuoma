# 市场预住院企业微信激励式推送设计

日期：2026-09-10

## 目标

在不改变现有登记入口、数据库集合和消息投递机制的前提下，增强企业微信群预住院消息的视觉层次，加入适度的员工激励，并把现有备注字段完整纳入推送。完成后同时审查页面易用性与可能导致登记失败的路径。

## 已确认范围

- 继续使用企业微信群机器人的 `markdown` 消息，不改为模板卡片，不增加图片或第二条消息。
- 不增加排名、个人累计、团队累计或目标完成率。
- 不改变患者姓名和联系电话完整显示的既有要求。
- 登记页面、数据校验和预住院记录中已经存在 `notes` 字段，本次只补齐通知模型与企业微信模板。
- 备注固定显示；为空时显示“未填写”。
- 真实群消息不可撤回，因此自动化验收不向真实企业微信群发送测试消息。

## 推送结构

消息按五个层级组织：

1. 标题：`🎯 新增预住院线索`。
2. 状态条：按联系结果使用企业微信 Markdown 的内置颜色。
3. 患者与历史摘要：姓名、完整联系电话、基本信息、既往住院次数、最近住院日期和患者类型。
4. 计划与跟进信息：计划住院日期、拟住院科室、主要问题、联系结果和备注。
5. 登记与激励信息：登记人员、简短感谢语、登记编号、登记时间和当前状态。

示例：

```text
### 🎯 新增预住院线索

<font color="info">● 有效意向线索｜建议优先确认</font>

**患者姓名**：测试患者
**联系电话**：13800000000
**基本信息**：女｜56 岁
**既往住院**：2 次｜最近 05月02日 至 05月08日
**患者类型**：普通居民医保

**计划住院日期**：2026-09-20
**拟住院科室**：风湿免疫科
**主要问题**：反复关节疼痛，希望进一步评估
**联系结果**：患者本人有意愿
**备注**：上午方便接听电话

🌟 **登记人员**：市场人员02
<font color="comment">感谢及时登记，请继续保持完整记录。</font>

**登记编号**：PY-20260910-0001
**登记时间**：2026-09-10 10:30
**当前状态**：待医务人员确认
```

## 状态与激励规则

| 联系结果 | 状态文字 | 颜色 | 行动提示 |
| --- | --- | --- | --- |
| 患者本人有意愿、家属有意愿 | 有效意向线索 | `info` 绿色 | 建议优先确认 |
| 正在考虑、暂未接通 | 待持续跟进 | `warning` 橙红色 | 请安排下一次联系 |
| 暂不考虑、其他 | 已完成触达记录 | `comment` 灰色 | 感谢完成真实记录 |

激励语只肯定及时、完整、真实的登记行为，不承诺患者住院结果，不使用排名或压力性文案。

## 备注数据流

`登记表单 notes` → `PreadmissionDraft` → `PreadmissionRecord` → `PreadmissionMessageModel` → `buildPreadmissionMarkdown` → 企业微信群。

- `notes` 在草稿和记录中继续限制为 500 字。
- 消息生成前继续使用 `safeInline`，移除换行、尖括号、反引号和方括号，避免用户输入破坏 Markdown 结构。
- 空备注统一显示“未填写”。
- 默认显示完整备注；如果完整消息超过企业微信 4096 字节限制，只在群消息中按 UTF-8 字节安全截短主要问题和备注并添加省略号，数据库中的完整内容保持不变。
- 推送失败后的重新推送从已保存记录重新构建消息，备注与首次保存内容保持一致。

## 错误处理与幂等

- 保持“先保存登记，再发送通知”的顺序，群推送失败不能丢失登记。
- 保持同一 `clientSubmissionId` 只创建一条记录，避免连续点击产生重复登记和重复消息。
- 保持 `sending`、`delivery_unknown`、`failed` 等状态及重试限制，不扩大自动重试范围。
- Markdown 内容必须保持在企业微信群机器人限制内；备注虽允许 500 字，整条消息仍应通过长度测试。

## 页面易用性与登记失败审查

实现通知改动后，对现有页面做一次限定范围的可用性和失败路径审查，重点验证：

- 历史患者与新患者都能进入登记流程。
- 姓名、联系电话、患者类型、计划住院日期、拟住院科室、主要问题和联系结果的必填提示明确。
- 备注为空或填写 500 字都能提交，超过限制在前端和服务端均被阻止。
- 网络失败、会话失效、权限不足、云函数异常和群推送失败都显示可理解的反馈，不把“已保存但推送失败”误报为“登记失败”。
- 保存过程中按钮不可重复点击；保存成功后表单锁定，并提供“开始下一位患者”。
- 390px 手机宽度下无横向溢出，输入控件和按钮触控高度不小于 44px，错误信息可被读屏软件感知。

发现明确、低风险且与登记可用性直接相关的问题时，纳入本次修复并补回归测试；需要改变业务规则或数据权限的问题只记录，不擅自扩展范围。

## 测试与发布

- 领域测试：三类状态条、备注有值、空备注、特殊字符清理、完整姓名和联系电话保留、敏感无关字段不进入消息、消息 UTF-8 字节长度不超过限制。
- 服务测试：通知模型包含已保存备注；首次推送和失败重试生成一致备注。
- 通知适配器测试：仍发送单条 `markdown` 消息，保持超时和企业微信错误码处理。
- 页面测试：备注输入与提交、重复提交保护、必填校验、错误反馈和新患者流程。
- 验证：完整测试、类型检查、云函数构建、静态页面构建、移动端浏览器检查和代码敏感信息扫描。
- 发布：部署 `marketPreadmission` 云函数；只有页面审查产生必要前端修复时才重新部署静态站点。
- 线上验收使用本地构造的合成数据检查消息文本，不主动调用真实企业微信 Webhook。
