# 诺玛元一企业微信问卷概要通知设计

## 目标

客户完成诺玛元一问卷并成功入库后，由 `submitSurvey` 云函数向指定企业微信群机器人推送一条可操作、脱敏的问卷概要。客户提交不依赖通知成功，群机器人异常不得影响问卷入库或客户看到的提交结果。

## 方案选择

考虑过三种方案：前端直接请求 Webhook、独立通知云函数、在现有提交云函数中发送。前端方案会泄露机器人密钥；独立函数增加事件系统和运维复杂度。采用现有提交云函数中的品牌化通知适配：它已掌握持久化后的标准记录，且已有企业微信地址校验、超时和失败隔离能力。

## 消息内容

诺玛元一消息使用企业微信 Markdown，包含：

- 品牌标题“诺玛元一｜新问卷概要”；
- 是否存在医学安全红旗；
- 记录编号与提交时间；
- 八维画像中“建议进一步评估”和“存在变化信号”的维度；
- 客户选择的最多三个 12 周目标。

消息不包含姓名、完整或脱敏手机号、逐题答案、红旗具体题目、性健康细节或任何开放文本。群成员需凭记录编号在受保护系统内查看完整资料。

## 路由与配置

- `male-health-v1.0` 继续使用 `HOSPITAL_WECHAT_WEBHOOK_URL` 和原医院消息。
- `nuoma-yuanyi-male-health-v1.0` 使用独立的 `NUOMA_YUANYI_WECOM_WEBHOOK_URL`。
- Webhook 只保存在 CloudBase `submitSurvey` 环境变量中，不进入源码、前端、GitHub、构建产物或日志。
- 仅允许 `https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...`。

## 数据流与错误处理

提交数据依次完成会话、身份、答案、评估和公共审计记录入库。之后按问卷版本选择通知配置和 Markdown 构建器。通知成功或失败都写入 `health_audit_logs`，动作为 `hospital_wecom_notification` 或 `nuoma_yuanyi_wecom_notification`，状态为 `sent`、`failed` 或 `not_configured`。错误日志只记录品牌化通用提示，不包含 Webhook。

同一 `clientSubmissionId` 的幂等重复提交沿用现有行为：直接返回既有结果，不重复发送群消息。

## 验证

- 单元测试覆盖诺玛元一内容、选项标签映射、隐私排除、官方地址校验和失败脱敏。
- 全量测试、类型检查、双品牌构建与生产依赖审计通过。
- 部署后发送一条明确标注“系统测试”的群消息，提交虚构问卷验证 `sent` 审计状态，随后按精确会话 ID 删除五类测试数据及审计记录。群消息无法自动撤回，应在消息中明确测试性质。
