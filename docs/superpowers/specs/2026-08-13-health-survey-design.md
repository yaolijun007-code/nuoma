# 建始民族医院健康与功能状态问卷设计

## 目标

建立一套公开链接即可填写、移动端优先、同时适合男性和女性的健康与功能状态问卷。第一版完整承载现有男性问卷 V1.0；界面与底层模型使用中性措辞和可扩展结构，为后续女性版本预留独立问卷配置。系统不诊断疾病、不计算衰老总分或身体年龄。

## 已确认决策

- 访问方式：任何人通过公开链接或院内二维码直接填写，无需注册。
- 身份字段：姓名、年龄、手机号后 4 位必填。
- 时间范围：除特别说明外，按过去 4 周填写。
- 结果：展示八个功能状态画像，不展示逐题得分。
- 医学红旗：第 49—55 题任一为“是”时优先临床评估，不自动生成常规干预方案。
- 视觉：鲜艳、高端、卡片式、男女通用；不采用“男蓝女粉”分色。
- 用户要求后续直接执行，不再通过问题中断。

## 范围

### 客户端

1. 欢迎页：机构、问卷版本、适用范围、预计时间、非诊断声明和隐私提示。
2. 基本信息：姓名、年龄、手机号后 4 位、日期、职业状态、优先改善问题和半年最明显变化。
3. 分模块答题：完整呈现第 1—55 题、补充文本项与个人健康目标。
4. 恢复：浏览器刷新后可恢复未完成会话；提交后清理本地健康答案。
5. 结果：八维状态卡、进一步评估线索和红旗安全提示。

### 服务端

1. 公开提交接口仅接受指定版本和通过结构校验的数据。
2. 以随机会话 ID 关联身份、答案和评估结果。
3. 身份信息、健康答案、评估结果和审计日志分集合保存。
4. 限流、蜜罐字段、请求大小限制和重复提交指纹用于抑制滥用。
5. 内部评估规则只在服务端运行；前端仅接收可展示结果。

### 管理端

第一阶段提供受保护的记录列表、红旗优先标识、详情、处理状态和 CSV 导出接口。管理端必须依赖 CloudBase 身份认证与角色校验，不能把管理密钥写入前端。

## 信息架构

问卷按 12 个客户可见步骤组织：基本信息、整体状态、精力恢复、睡眠、压力认知、胃肠排便、代谢体感、心肺肌肉、男性健康、生活方式、医学安全、12 周目标。内部规则不成为客户步骤。

每个步骤使用一致的题目数据结构：

```ts
type Question = {
  id: string;
  number?: number;
  prompt: string;
  type: "single" | "multi" | "text" | "date" | "number";
  options?: { value: string; label: string; score?: number }[];
  required?: boolean;
  maxSelections?: number;
  helper?: string;
};
```

题目文案与分值相互分离。状态计算只能使用服务端持有的评分映射。

## 视觉系统

设计主题为“生命光谱”：用连续的蓝紫、湖青和珊瑚橙光谱表达多维健康状态，避免性别化配色。独特视觉标志是一条随问卷进度缓慢变化的光谱轨道，既承担进度功能，也形成品牌记忆。

色彩使用 OKLCH：

- `--ink: oklch(0.22 0.035 260)`：正文与深色标题。
- `--paper: oklch(0.985 0.008 245)`：主背景。
- `--violet: oklch(0.62 0.24 292)`：主品牌与选中态。
- `--cyan: oklch(0.75 0.16 205)`：进度与辅助高光。
- `--coral: oklch(0.72 0.19 35)`：行动按钮与提醒。
- `--safe: oklch(0.69 0.17 155)`：稳定状态。
- `--danger: oklch(0.58 0.22 25)`：医学安全信息，仅用于必要位置。

大面积背景保持低色度，鲜艳色用于进度、选择反馈和局部光晕。正文对比度满足 WCAG AA；焦点环与错误状态不只依赖颜色。动效尊重 `prefers-reduced-motion`。

字体优先使用本地系统中文字体栈，避免外部字体服务造成隐私与加载风险。标题以紧凑字距和强弱对比建立高级感，正文保持 16px 以上。

## 数据与隐私

- 姓名和手机号后 4 位属于识别信息，与回答分集合保存。
- 浏览器本地草稿设置过期时间；提交成功后立即清除。
- 公共客户端没有列表、搜索或读取他人记录的能力。
- 生产数据库默认拒绝客户端直读，提交经云函数完成。
- 管理员操作生成审计日志。
- 数据保存期限、医院隐私告知文本与删除流程由院方在正式生产前确认。

## 评估与安全

八个输出方向为：精力与恢复、睡眠与日间状态、压力与认知、胃肠与排便、代谢相关体感、心肺与运动、肌肉与功能储备、男性活力与泌尿。

每个方向输出 `stable`、`signal`、`evaluate`；医学红旗额外输出 `clinical_priority`。触发器保留机器代码和中文解释，供管理端审阅。不得仅凭问卷输出疾病名称。

## 错误处理

- 必填题缺失：停留在当前步骤，将错误关联到具体控件并聚焦首个错误。
- 网络失败：保留草稿并提供明确重试入口。
- 重复提交：返回原提交确认号，不创建重复健康记录。
- 服务端校验失败：不落库，不在错误信息中回显敏感答案。
- 红旗答案：提交成功，但结果页进入临床优先提示模式。

## 验收

- 320px 至桌面宽度均无横向溢出。
- 键盘可完成全部填写，焦点可见，错误可被读屏识别。
- 55 道编号题、基本信息和目标选择均可保存与恢复。
- 所有内部触发规则有单元测试；红旗覆盖第 49—55 题。
- 类型检查、单元测试、构建和端到端核心流程通过。
- GitHub 不包含云密钥或真实健康数据。
