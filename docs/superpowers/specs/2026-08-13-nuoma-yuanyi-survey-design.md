# 诺玛元一健康问卷品牌副本设计

## 目标

在不改变现有“建始民族医院”公开问卷的前提下，新增一套内容与评估逻辑相同、品牌与视觉完全独立的“诺玛元一”问卷。新版本继续保持公开链接直接填写、无需注册、移动端优先、非诊断性评估和医学红旗优先处理。

用户此前已明确要求后续直接执行、不再通过问题中断。本设计据此自主确定视觉方向与工程方案。

## 方案比较与选择

### 方案A：复制整套前端源码

两份应用分别维护。优点是隔离直观；缺点是55题、评估规则、无障碍行为和安全修复会逐渐分叉，长期维护成本最高。

### 方案B：单一构建，运行时根据URL切换品牌

一个构建产物同时响应两个路径。部署最简单，但静态托管的页面元数据、资源基础路径和缓存边界不够清晰。

### 采用方案：共享问卷内核，品牌化构建两套静态产物

题目、校验、评估和提交服务只保留一份；品牌名称、中心副标题、视觉主题、问卷版本、草稿键和部署基础路径由品牌配置注入。默认构建仍生成建始民族医院版本；诺玛元一构建生成独立目录和独立版本。

## 品牌与信息架构

- 公司名称：诺玛元一。
- 产品副标题：生命健康管理。
- 问卷名称：健康与功能状态问卷。
- 适用内容：完整复制当前男性健康V1.0题目、八维结果与医学安全规则。
- 公开路径：`/nuoma-yuanyi-survey/`。
- 问卷版本：`nuoma-yuanyi-male-health-v1.0`。
- 本地草稿键：与医院版独立，避免同一设备上的草稿覆盖。
- 服务端存储：继续使用现有五类安全集合，以 `questionnaireVersion` 区分来源；身份、答案、结果和审计仍通过 `sessionId` 关联。

## 视觉系统

主题命名为“翡翠生命力”。它避开当前蓝紫、湖青和珊瑚组合，使用更鲜明但克制的生命科学配色：

- `--ink`：深海墨绿，用于标题、导航和高对比文字。
- `--paper`：暖瓷白，用于大面积背景，降低医疗场景中的屏幕疲劳。
- `--emerald`：电光翡翠，用于主品牌、进度与选中态。
- `--mint`：清透薄荷，用于柔和光晕和次级状态。
- `--gold`：香槟金，用于关键行动、数字与精细分隔。
- `--danger`：清晰朱红，仅用于错误和医学安全提示。

欢迎页采用深色品牌舱与暖白内容卡叠合，标题保留大字号但减少彩虹渐变。品牌标志改为“元点＋轨道”的几何结构：中心金色圆点象征“元一”，翡翠轨道象征持续健康管理。答题页使用暖白卡片、墨绿标题、翡翠选中边和金色进度节点，形成鲜艳、现代、男女均适用的高端观感。

动效仅使用透明度、位移与合成层渐变；尊重 `prefers-reduced-motion`。正文、按钮、焦点环和错误状态满足WCAG AA，信息不只依赖颜色表达。

## 组件与构建边界

新增品牌配置模块，提供：

- 机构名称与副标题；
- 欢迎页眉文案；
- `questionnaireVersion`；
- `draftStorageKey`；
- `themeClass`；
- Vite静态资源基础路径。

`App`、品牌标志、草稿服务和提交服务消费同一品牌配置。Vite根据 `VITE_SURVEY_BRAND` 选择配置，并通过独立脚本输出诺玛元一版本。医院版现有构建命令和线上目录保持兼容。

服务端接受两个明确列入白名单的版本号，两者使用相同题目结构和评估规则。任何未知版本继续返回400，不扩大公开接口的接受范围。

## 数据流与安全

1. 客户打开诺玛元一公开路径，静态产物加载诺玛元一品牌配置。
2. 草稿只写入诺玛元一专用本地键，48小时过期。
3. 提交载荷携带诺玛元一版本号，服务端完成题目完整性校验和评估。
4. 会话记录保存品牌版本；身份、答案和评估结果分集合保存。
5. 红旗题继续将所有维度提升为临床优先，不生成常规管理建议。
6. 公开页面仍无任何记录读取接口。

## 错误处理

- 构建品牌值未知：构建立即失败，不回退到错误品牌。
- 服务端版本未知：返回 `INVALID_PAYLOAD`，不落库。
- 网络失败：保留对应品牌草稿并允许重试。
- 重复提交：以品牌专属客户端提交ID幂等返回原确认号。
- 视觉主题缺失：测试阻止发布，不允许无品牌样式上线。

## 测试与验收

- 默认构建仍显示建始民族医院，路径仍为 `/health-survey/`。
- 诺玛元一构建只显示诺玛元一品牌，路径为 `/nuoma-yuanyi-survey/`。
- 两套版本使用不同的问卷版本和草稿键。
- 服务端接受两个白名单版本，拒绝未知版本。
- 55道编号题、八维画像、红旗处理、身份分离和幂等行为不变。
- 320px、390px、桌面宽度无横向溢出；键盘、焦点和错误播报可用。
- 诺玛元一线上HTML、JS、CSS及提交接口均验证成功。
- 虚构验收数据在核验后逐条删除。
- GitHub CI通过后才视为完成。
