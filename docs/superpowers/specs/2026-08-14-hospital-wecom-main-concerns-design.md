# 建始民族医院问卷企业微信通知设计

## 目标

建始民族医院问卷成功入库后，由现有 `submitSurvey` 云函数向指定企业微信群机器人推送一条精简通知。通知只展示姓名、完整手机号和客户选择的主要问题，方便院内人员及时跟进；客户提交不得依赖群机器人成功响应。

## 已确认的现有能力

- 医院版问卷使用版本 `male-health-v1.0`，收集完整 `phone`，并在服务端派生 `phoneLast4`。
- `topConcerns` 要求客户选择3个最希望优先改善的问题，选项标签由医院版问卷定义维护。
- `submitSurvey` 在五类记录入库后调用现有企业微信通知适配器，并将 `sent`、`failed` 或 `not_configured` 写入审计日志。
- Webhook 已设计为 CloudBase 环境变量 `HOSPITAL_WECHAT_WEBHOOK_URL`，不会进入前端、GitHub 或构建产物。
- 诺玛元一使用独立环境变量和独立消息模板，本次不修改。

## 方案选择

采用现有云函数入库后通知方案。客户端直连会暴露机器人密钥；独立轮询服务会增加延迟、部署和运维成本。现有链路已经具备品牌路由、超时、Webhook 域名校验、错误隔离和审计能力，只需调整医院版消息生成逻辑并更新云端变量。

## 消息结构

企业微信消息类型继续使用 `markdown`：

```text
### 建始民族医院｜新问卷
> 姓名：张三
> 手机号：13800138000
> 主要问题：精力不足、睡眠、压力与情绪
```

规则：

- 姓名来自已归一化的 `record.identity.name`。
- 手机号来自医院版完整 `record.identity.phone`；只有合法11位中国大陆手机号才展示，否则显示“未提供”。
- 主要问题来自 `record.healthAnswers.topConcerns`，根据医院版 `topConcerns` 选项映射为自然语言，最多展示3项并去重。
- 无法映射时显示“未填写”，不回显任意未知值。
- 所有文本在插入 Markdown 前移除换行和控制性标记，防止消息结构被用户输入破坏。
- 不附加逐题答案、医学安全答案、评估结果、开放文本、记录编号或提交时间。

## 数据流与边界

1. 客户提交医院版问卷。
2. 云函数完成校验、归一化、评估和五集合入库。
3. 通知路由只对 `male-health-v1.0` 且存在完整手机号的记录生成医院消息。
4. 云函数从 `HOSPITAL_WECHAT_WEBHOOK_URL` 读取机器人地址并发送。
5. 企业微信成功返回 `errcode: 0` 时审计状态为 `sent`；缺少配置为 `not_configured`；超时、网络异常或企业微信拒绝为 `failed`。
6. 第4—5步的任何失败均不回滚已入库问卷，也不改变客户提交成功结果。

## 安全与隐私

- Webhook 只允许官方 HTTPS 域名 `qyapi.weixin.qq.com` 和 `/cgi-bin/webhook/send` 路径。
- 密钥只保存在 CloudBase 云函数环境变量，不写入源码、文档、命令输出、前端变量或日志。
- 日志只记录固定错误文案与审计状态，不记录 Webhook、姓名、手机号或主要问题。
- 群内将出现完整手机号，因此该机器人应仅加入经授权的院内工作群；这是本次用户明确要求的数据展示范围。

## 测试与部署

- 单元测试先证明医院消息包含3个指定字段、正确选项标签与完整手机号，并且不再包含旧消息中的记录编号、时间和状态。
- 测试手机号异常、未知主要问题值、重复选项和用户输入换行的安全降级。
- 回归验证诺玛元一消息与品牌路由不变。
- 重新生成 CloudBase 云函数单文件构建，执行全量测试、类型检查和双品牌构建。
- 在 CloudBase 更新 `HOSPITAL_WECHAT_WEBHOOK_URL`，重新部署 `submitSurvey`。
- 用明确标注的虚构医院问卷完成一次真实提交，确认企业微信返回成功、五集合版本正确、通知审计为 `sent`，随后按精确 `sessionId` 删除虚构健康数据。

## 非目标

- 不修改问卷题目、评分规则、页面样式或诺玛元一通知。
- 不增加企业微信卡片按钮、群内健康评分或医学红旗详情。
- 不在群内存储或展示完整问卷答案。
