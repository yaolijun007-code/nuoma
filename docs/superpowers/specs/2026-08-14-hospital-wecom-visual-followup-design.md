# 建始民族医院企业微信可视化跟进通知设计

## 目标

将医院问卷现有“姓名、手机号、主要问题”通知升级为方案二的分级跟进消息。消息在企业微信手机端一屏内呈现客户身份、联系重点、跟进等级、简明状态概览和追溯信息；不发送逐题答案、具体医学安全答案或疾病诊断。

## 平台约束与方案选择

企业微信群机器人现有链路使用官方 `markdown` 消息。Markdown 支持标题、引用、粗体和 `info`、`comment`、`warning` 字体颜色，适合用 Emoji、颜色标签与一行状态分布强化层级。独立图片需要第二次请求，增加频率、失败点和健康信息扩散面；模板卡片还需要有效的跳转动作，而当前没有面向单条记录的安全管理页面。

因此继续发送一条 Markdown 消息，不引入外部图标、图片托管或管理后台链接。

## 消息结构

```text
### 🏥 建始民族医院｜新健康问卷

🚦 **跟进等级**：<font color="warning">建议重点跟进</font>

👤 **姓名**：张三
📱 **手机号**：13800138000
🎯 **主要问题**：① 睡眠　② 精力不足　③ 压力与情绪
🔎 **最明显变化**：睡眠变差
⭐ **首要改善目标**：睡眠

📊 **状态概览**：<font color="warning">评估 2</font>｜<font color="comment">变化 1</font>｜<font color="info">稳定 5</font>

🕒 **提交时间**：08月14日 15:30
🧾 **记录编号**：JS-EXAMPLE
```

消息保持四段：标题、跟进等级、客户与沟通重点、状态和追溯信息。图标仅用于固定字段标题，不根据客户输入生成。

## 字段映射

- 姓名：`record.identity.name`，继续使用单行安全过滤。
- 手机号：`record.identity.phone`，合法11位大陆手机号完整展示，否则显示“未提供”。
- 主要问题：`healthAnswers.topConcerns` 映射医院版选项标签，去重后最多3项，以 `① ② ③` 表示顺序。
- 最明显变化：`healthAnswers.mainChange` 映射医院版 `mainChange` 选项；未知或缺失值显示“未填写”。
- 首要改善目标：`healthAnswers.singleImprovement` 使用 `topConcerns` 同一标签表映射；必须是客户已选的关注项，否则显示“未填写”。
- 提交时间：`session.submittedAt` 以 `Asia/Shanghai` 转换为 `MM月DD日 HH:mm`；无效时间显示“时间待核实”。
- 记录编号：`session.confirmationId`。

未知选项值永不原样回显，避免把非白名单内容带入群消息。

## 跟进等级

按优先顺序只输出一个等级：

1. `session.hasRedFlag` 为真：`需医务人员优先核实`，使用 `warning` 色。群内不显示红旗题目或答案。
2. 无红旗且 `evaluate` 方向不少于2个：`建议重点跟进`，使用 `warning` 色。
3. 无红旗且存在至少1个 `evaluate` 或 `signal` 方向：`存在变化信号`，使用 `comment` 色。
4. 其他：`常规健康管理`，使用 `info` 色。

该等级用于安排人工跟进顺序，不是疾病诊断、衰老评分或身体年龄。

## 状态概览

无红旗时统计八维评估中：

- `evaluate` 数量显示为“评估”；
- `signal` 数量显示为“变化”；
- `stable` 数量显示为“稳定”。

这是一行分类计数，不绘制比例条或百分比，避免把未经验证的分类误解为健康分数。

存在红旗时不显示被统一提升后的八维数量，改为：

```text
📊 状态概览：安全信息待人工核实
```

## 安全和失败策略

- 仍只对 `male-health-v1.0` 使用该消息，诺玛元一消息保持不变。
- Webhook 继续只存在于 CloudBase `HOSPITAL_WECHAT_WEBHOOK_URL`。
- 发送失败写 `hospital_wecom_notification` 审计状态，但不回滚问卷或改变客户提交结果。
- 日志不记录姓名、手机号、主要问题、Webhook 或具体红旗内容。
- 群内包含完整手机号，机器人仅可加入经授权的院内工作群。

## 测试与验收

- 先以精确 Markdown 快照测试跟进等级、图标、三个关注项、变化、目标、状态概览、上海时间和记录编号。
- 分别测试红旗、重点跟进、变化信号、常规管理四个等级。
- 测试未知值、重复问题、非法手机号和无效时间的安全降级。
- 回归验证诺玛元一消息和 Webhook 主机校验不变。
- 重新生成云函数单文件包，执行全量测试、类型检查、双品牌构建和生产依赖审计。
- 部署 `submitSurvey` 后用明确标记为虚构的医院问卷提交一次，确认审计状态为 `sent`，再按精确会话 ID 删除五集合测试记录。

## 非目标

- 不发送PNG/JPEG图表或第二条群消息。
- 不增加客户详情跳转链接或后台管理页面。
- 不发送八维原因、建议、逐题答案、具体红旗内容或诊断结论。
- 不修改问卷页面、题目、评估阈值或诺玛元一通知。
